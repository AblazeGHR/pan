## 优先级 1：历史重放截断

**问题**：
- `_consumer_mcp` 每次调用重放全部 `s.history`，上下文随消息数线性膨胀
- 61 条历史时，后续消息退化到本地文件探索，不再调 MCP

**方案**：

```python
# _consumer_mcp 中修改历史重放逻辑
MAX_HISTORY_FOR_REPLAY = 6  # 只重放最后 3 轮对话

if s.history and len(s.history) > 1:
    recent = s.history[-MAX_HISTORY_FOR_REPLAY:]  # 截断
    history_context = _format_history_for_context(recent)
    if history_context:
        text = f"[上下文摘要：之前讨论了COC跑团游戏管理...]\n{history_context}\n[User]: {text}"
```

**替代方案**：重新评估 `--resume` 选项
- 之前放弃 `--resume` 因为 cli_session_id 不匹配
- cbc 的 session_id 是 UUID，与 Pan session 无关
- 需要在 `_consumer_mcp` 首次调用时保存 init 事件的 session_id，后续调用时传 `--resume`
- cbc 内部维护对话历史，不需要 Pan 重放

## 优先级 2：首条消息性能优化

**相关方案**：[session 克隆避免冷启动](./session-克隆避免冷启动.md) — 通过分支已探索的 session 继承上下文

**问题**：
- 新 session 首条消息 ~90s（20+ 次本地工具调用：Bash/Grep/Agent 探索 Pan 项目）
- 模型需要探索代码库才能理解 "RuleWhisper is connected"

**方案**：

在 system_prompt 中加入项目背景：
```
系统信息：你正在 Pan CLI Agent 项目中作为 COC 守秘人运行。
Pan 已将 RuleWhisper MCP 服务器 (rulewhisper) 配置并连接。
项目工作目录由 -d 参数指定，不需要探索项目代码结构。
当玩家提出游戏操作请求时，直接使用 RuleWhisper MCP 工具。
```

这样模型不需要探索项目就能直接使用 MCP 工具。

## 优先级 3：cbc 调用模式优化

**问题**：
- 每次用户消息都新开 cbc 进程（`asyncio.create_subprocess_exec`）
- 进程启动 ~2s + MCP server 初始化 ~5s = 每次 ~7s 冷启动
- 不支持对话连续性（每次都是新 session）

**方案**：

### 3a. `--resume` 模式（推荐优先尝试）

```python
# _consumer_mcp 中
if s.cli_session_id:
    args.extend(["--resume", s.cli_session_id])
else:
    # 首次调用，解析 init 事件获取 session_id
    pass

# 后续调用时
# cbc 内部维护对话历史，Pan 不需要重放
```

### 3b. 长连接 MCP

如果 cbc 未来支持 `--input-format stream-json --mcp-config` 同时使用，则切换回 stream 模式。

## 优先级 4：错误处理与稳定性

**问题**：
- cbc 进程超时(120s)后 worker 可恢复

**方案**：

```python
# _consumer_mcp 增加回退逻辑
MCP_TIMEOUT = 60  # 首块数据超时

if output_received and "mcp__" not in output:
    _log.warning("MCP tools not used, fallback to stream mode")
    # 或标记 session 以在下次转回 stream 模式
```
