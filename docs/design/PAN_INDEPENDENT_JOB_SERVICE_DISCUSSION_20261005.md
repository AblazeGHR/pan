# 独立 Job 服务拆分方案（讨论稿）

日期：2026-10-05。状态：**待讨论，不是批准实施的接口或部署方案**。

本文只提出拆分方向，不安装服务、不迁移线上数据、不改变 Pan 的停止行为。
现有实现背景见 [Background Jobs](background-jobs.md)，测试隔离要求见
[测试约定](../TESTING.md)。

## 1. 目标与问题边界

让本质上不依赖 Pan 的后台命令和定时任务，在 Pan 关闭、崩溃或重启时继续运行；
Pan 提供快捷创建、查看、取消、重试和结果接收入口，而不是任务必须存活的宿主。

当前后台 Runner 已是独立进程，但“独立进程”不等于“独立生命周期”：
Pan 启动的后代仍可能被整树终止或继承的 Windows Job 约束连带终止。
当前调度和 Session 结果投递也由 Pan 内的恢复循环驱动。
实际 Pan 重启时现有 Runner 是否存活，仍不能用静态代码检查替代实测。

本方案解决的是 **Pan 生命周期耦合**，不自动解决机器掉电、任务自身崩溃、
任意外部副作用的重复执行、环境污染、所有 Windows Job 布局或远程鉴权。

## 2. 职责拆分

```text
Pan：UI / Agent API / Session 集成
       ↕ 创建、查询、取消、结果拉取与确认
独立 Job 服务：任务登记 / 调度 / Runner 管理 / 日志 / 结果 outbox
       ↕ 启动与身份核验
任务进程：命令、脚本及其自有后代
```

| 组件 | 负责 | 不负责 |
| --- | --- | --- |
| Job 服务 | 任务事实、调度触发、执行、取消、恢复、日志、持久化结果事件 | Pan Session/Worker 生命周期、聊天历史、浏览器鉴权 |
| Pan | 管理入口、权限上下文、任务展示、Session 消息投递和确认 | 以自身退出隐式终止独立任务；重复维护另一套调度事实 |
| Runner | 单次执行、输出、退出结果、所属进程树 | 调度周期、Session 投递、独立服务全局管理 |

初期复用现有 Runner、日志和身份核验能力，不另造通用工作流平台。
内部服务是否复用 JSON 存储，还是使用事务数据库，应按单写者和恢复需求讨论，
不在本稿中提前冻结。迁移期不允许 Pan 与新服务同时调度同一任务。

## 3. 哪些任务可以离开 Pan

| 任务 | Pan 不在线时 |
| --- | --- |
| 后台 argv 命令、脚本、文件处理 | 独立执行并保存结果 |
| 定时触发上述命令 | 独立调度、执行和记录每次 occurrence |
| 给 Session 发消息、广播、启动 Pan Agent | 保存待执行事件；依赖 Pan 恢复，不假称业务已执行 |
| 未来 HTTP/其他外部动作 | 逐项定义执行器、凭据和重试契约，不默认纳入首版 |

任务类型必须显式标记依赖。与 Pan 无关的任务不应为了执行而加载 Session、
Worker、provider 或完整 Web 服务；依赖 Pan 的任务通过适配层调用。
调度器“触发成功”、Pan“接收事件”、Agent“读到消息”和业务“完成”是不同事实。

## 4. 服务宿主与管理语义

服务必须由 **Pan 之外的宿主**启动，不能仅换成 Pan 子进程 daemon。
Windows 可选服务管理器（SCM）或外部用户级常驻宿主；具体选择待讨论。
需要核对运行账户、用户 profile、工作目录、工具链、用户态凭据/DPAPI 的可用性，
不能默认切换为系统账户后行为仍一致。

- 关闭或重启 Pan，默认不停止 Job 服务，也不取消独立任务。
- 启停 Job 服务是单独管理操作；Pan 可以请求，生命周期不绑定 Pan lifespan。
- 明确区分“停止接单/排空”“停止服务”“取消某个任务”“终止所有任务”。
- Pan 连接失败显示服务不可用，不制造任务 failed 或重复启动第二个执行服务。
- 单实例 ownership 必须阻止两个服务同时 claim；服务重启核对既有 Runner，
  不因服务进程退出就立即判任务结束，也不无证据重发任务。

SCM 可独立启动和管理服务；Windows Job 的子进程关联与 breakaway 受父 Job
策略限制。宿主选择后仍需真实生命周期测试，而不是只检查 detached 标志。
参考：[SCM](https://learn.microsoft.com/en-us/windows/win32/services/service-control-manager)、
[Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)。

## 5. 持久化、执行与取消

建议保持三类独立对象：任务定义、单次运行（run）、结果事件。
周期任务每次触发产生独立 runId，不反复覆盖上一轮事实。

- 登记先持久化再启动；恢复时核对 Runner PID 与创建时间/FILETIME。
- ALIVE、DEAD、UNKNOWN 分开；未知不能伪造死亡、杀错 PID 或删除恢复凭据。
- 创建请求允许幂等键；相同键不得由于 Pan 重试再启动一次。
- 取消只作用于已核验的自有任务树，不按名称或单 PID 广杀。
- 未证明收敛保留 owner/状态与可重试入口，不假报 cancelled/completed。
- Retry 是新运行，保留来源；不自动宣称任意命令可安全重试。
- 服务/Runner 崩溃时可能存在“副作用已发生但结果未提交”的窗口；
  不承诺通用 exactly-once 执行。需显式采用失败、人工确认或业务幂等策略。

## 6. 定时任务契约

首版优先延续 once、interval、weekly，不急于增加复杂 cron。
必须在实施前定清楚：

- 时区、夏令时重复/缺失时刻，以及系统时钟变更处理。
- 服务停机后的 misfire：跳过、补一次、还是限量补跑；不能默认无限补发。
- 重叠执行：禁止重叠、排队或有限并发；上一轮未结束时不得隐式无限累积。
- occurrence 唯一键与 claim 持久化，防止重启/并发导致同一次双触发。
- 对 Pan 依赖动作：到期事实先保存，Pan 离线时等待；过期/补发单独定义。

现有 recurring 消息恢复采用补一次、从恢复时间计算后续时刻等语义；
迁移时须明确保留还是变更，不静默改动已有任务的用户预期。

## 7. 结果补投与 Pan 重连

Job 服务先保存终态和持久化 outbox，再向 Pan 提供结果拉取/订阅。
Pan 离线不丢结果；恢复后消费，按稳定 eventId 去重，再确认。

事件至少区分 jobId、runId、eventId、终态和目标路由。
目标 Session 已删除时保留任务结果，显示不可投递或允许显式改路由；
不能为了消除 pending 而伪造已送达。outbox 的保留/清理策略也必须明确。

确认边界建议为“Pan 已持久化到目标队列”，不是“Agent 已阅读”。
投递成功但确认丢失时允许重传，接收侧需幂等。
Pan UI/API 只读服务事实，不再自行根据句柄 poll 等局部证据改写终态。

## 8. 配置与测试隔离

独立服务有自己的显式数据根、实例身份和配置入口；任务环境采用明确构建规则，
不盲目继承 Pan 全部 PAN_* 应用变量。任务特需变量可以显式传入，秘密不得进日志。
把所有设置搬进 config.json 不是充分解决方案：错误路径、共享数据根和导入副作用
仍可能污染实用实例。关键是所有权清楚、默认隔离和可核验的实际解析路径。

测试使用临时服务实例和数据根，遵循 docs/TESTING.md；构造哨兵实用目录，
验证测试前后不变。停止测试实例不得影响实用 Job 服务或用户任务。
任意现有 cwd 是已授权能力，不重新引入仓库目录沙箱；数据根与 cwd 是不同概念。
远程暴露/认证不在本稿批准范围，后续单独讨论，不能把配置开关当鉴权。

## 9. 低风险实施顺序（提案）

1. 冻结生命周期、任务/运行/事件模型、定时策略和宿主选择。
2. 隔离实现最小 Job 服务：后台 argv + 查询/取消 + 日志 + outbox。
3. 验证 Pan 优雅退出、强制整树终止、服务重启下的自有任务和结果恢复。
4. Pan 增加客户端适配，保持已有 UI/MCP 入口；先不迁移线上存量。
5. 迁移定时命令与 Pan 依赖适配；单写者切换、历史 ID/权限/结果路由保留。
6. 授权后迁移存量与部署；提供回退方案。回退也必须保证唯一调度权，
   不通过重跑所有存量任务来“恢复”。

首版避免额外队列平台和分布式调度；先把本机生命周期闭环做实。

## 10. 验收与待讨论决策

验收至少包括：Pan 优雅/强制退出任务不停；Pan 离线定时命令仍触发；
结果恢复投递不丢失、不重复入队；服务重启不重复执行；错身份取消零触碰；
并发 create/claim、取消与完成交错；环境污染哨兵；调度补跑与重叠策略；
测试服务停止不影响实用实例。机器重启只按已定义恢复策略验收，不默认进程可存活。

后续讨论重点：

- SCM 还是外部用户级宿主？登录前运行是否必要？
- 初期迁移哪些 Job 类型，哪些明确保留 Pan 依赖？
- 停止服务时排空/保留 Runner/取消的默认策略是什么？
- 定时补跑、重叠和失败重试的默认值是什么？
- 存储与 outbox 是否需要事务数据库？如何单写者切换与回退？
- Pan 不在线期间，结果保留多久，目标 Session 消失如何处理？

这些问题未定前，不把本文视为实现任务书，也不宣称独立 Job 服务已经存在。
