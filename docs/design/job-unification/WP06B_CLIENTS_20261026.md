## 共享客户端与授权

`packages/jobs/final_client.py` 是 MCP/CLI 共用的请求构造与 WP01 校验层；不引入
调度器、存储、执行器或自动重试。MCP 的 transport 使用既有 authorization_objects
私有 IPC 桥，随后以 HTTP ASGI 请求调用原 canonical router。
allowlist 仅新增明确的 `/api/final` 资源路径，原 `object_path` 与旧白名单保留。
canonical 错误直接保留服务返回的 code/path/details，不压扁成旧数字错误。

MCP 使用当前 profile 的 Agent grants，无 User Bearer；客户端不能自报 principal。
SSE/streamable HTTP 的 canonical 调用返回 `authorization_denied`。
除 main() 的 transport 设置外，还检查 FastMCP 的真实 HTTP request context，防止 gateway
直接导入 registry 时沿用模块默认 stdio，并借用继承的本地 IPC。
CLI 走同一 CanonicalClient 的 HTTPTransport，使用 `PAN_API_TOKEN` 中的现有 User session Bearer，
不依赖 Agent grants、不签发 token、不自动登录。token 不作为命令行参数或报告内容。

写操作保留 requestKey/operationId，accepted/pending 只表示接纳，不证明效果成功。
超时/连接或响应无法确认时返回 `transport_unconfirmed`；不重试、不跟随重定向。
未知结果使用 `job_operation_get/find` 或 CLI 原身份查询。手动 Run 准入在 WP06a
回执空间的 operation 为 **create**，不是 run；应保存原 requestKey。
Run Retry 保持原 Run，Run again 新建 Run，Clone and run 新建 Job/Run；客户端不模拟这些语义。

## CLI 命令与请求体

入口 `pan final`，等价于 `python -m packages.core.cli final`。
`--api-url` 位于 final 后；优先级为显式参数、PAN_API_URL、注册 checkout 的配置端口。
canonical 命令不调用 start/stop/restart，也不读取旧 Job JSON 作为事实源。
既有 host CLI 命令及其环境清理策略保持原行为。

```text
pan final --api-url http://127.0.0.1:<port> jobs list [--limit 1..100] [--cursor CURSOR]
pan final --api-url URL {jobs,triggers,event-creators,job-templates} get ID
pan final --api-url URL {jobs,triggers,event-creators,job-templates} create --file create.json
pan final --api-url URL {jobs,triggers,event-creators,job-templates} update ID --file update.json
pan final --api-url URL {jobs,triggers,event-creators,job-templates} retire ID --file retire.json
pan final --api-url URL {jobs,triggers,event-creators,job-templates} control ID --file control.json
pan final --api-url URL jobs runs JOB_ID [--limit N] [--cursor CURSOR]
pan final --api-url URL jobs run JOB_ID --file run.json
pan final --api-url URL job-runs get RUN_ID
pan final --api-url URL job-runs {retry,run-again,clone-and-run,cancel,pause,resume} RUN_ID --file operation.json
pan final --api-url URL operations get OPERATION_ID
pan final --api-url URL operations find --file original-request.json
pan final --api-url URL actions list
```

花括号表示备选子命令，不是输入字符。`--file -` 从 stdin 读严格 JSON，拒绝重复键、
NaN/Infinity 和超过 WP01 字节上限的请求。create 文件是完整
`{definition,expectedRevision:0,requestKey}`；update 使用 expectedRevision>=1。
retire 为 `{expectedRevision,expectedStateRevision,requestKey}`；control 另含 operation/parameters。
run 为 `{expectedRevision,requestKey,input:{},cause:{type:"manual"}}`，可选 rerunOf。
retry/cancel/pause/resume 为 `{expectedStateRevision,requestKey}`；retry 可含 stepId。
run-again/clone-and-run 另须 expectedRevision，可选 parameters。
operations find 为 `{operation:"create",requestKey:"原 Run 准入 key"}`。

stdout 是原 JSON 结果。错误、rejected、unknown 返回退出码 1；accepted/pending/completed
返回 0，但 0 不能替代 operation 终态查询。argparse 参数错误返回 2。
