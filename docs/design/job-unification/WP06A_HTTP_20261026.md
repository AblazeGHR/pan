基线 `b63861569232c168fadb4ab62946e19101315473`。
本包实现 HTTP/service 接线，不切换 MCP、CLI 或 React，不迁移真实数据。

## 过渡路径：`/api/final/*`

按 MA 后续裁决，WP07 切换前，旧 `/api/jobs` 与所有既有子路径保持原 URL、
原 handler 和原业务行为。没有 `/api/legacy/jobs` 重定位，也没有按旧 `kind`
向 canonical 写接口分流。server 同时注册旧 router 和唯一的 canonical router；
旧路由的 OpenAPI metadata 标记 `deprecated` / `legacy-jobs`。
因此 RETIREMENT_INVENTORY 的旧入口尚未退场，不能宣布 R3/R5 已关闭。

本包所有新路由使用临时 `/api/final` 前缀。WP01 的字段、校验器、schema URL
与操作语义不变；原设计中的无前缀路径留待客户端切换后由整合包处理。

| 方法 | 临时路径 | 含义 |
|---|---|---|
| GET / POST | `/api/final/jobs` | 列表 / 创建定义 |
| GET / PUT / DELETE | `/api/final/jobs/{id}` | 读取 / 全量更新 / retire |
| POST | `/api/final/jobs/{id}/operations` | enable/disable/pause/resume/retire |
| GET / POST | `/api/final/jobs/{id}/runs` | Run 分页 / 手动准入，支持 rerunOf |
| GET | `/api/final/job-runs/{runId}` | WP01 Run 记录 |
| POST | `/api/final/job-runs/{runId}/operations` | retry/run-again/clone-and-run/cancel/pause/resume |
| GET / POST | `/api/final/triggers` | 列表 / 创建纯准入 Trigger |
| GET / PUT / DELETE | `/api/final/triggers/{id}` | 读取 / 更新 / retire |
| POST | `/api/final/triggers/{id}/operations` | 生命周期控制 |
| GET / POST | `/api/final/event-creators` | 列表 / 创建来源实例 |
| GET / PUT / DELETE | `/api/final/event-creators/{id}` | 读取 / 更新 / retire |
| POST | `/api/final/event-creators/{id}/operations` | 生命周期控制 |
| GET / POST | `/api/final/job-templates` | 列表 / 创建完整被动 Template |
| GET / PUT / DELETE | `/api/final/job-templates/{id}` | 读取 / 更新 draft / retire |
| POST | `/api/final/job-templates/{id}/operations` | publish/retire |
| GET | `/api/final/actions` | 只读的产品/provider published Action 目录与 Ref 材料 |
| GET | `/api/final/operations/{id}` | 按原操作身份查询 |
| GET | `/api/final/operations?operation=...&requestKey=...` | 同 principal/profile 的原请求恢复 |

合计 31 个方法入口。定义写体为 `{definition,expectedRevision,requestKey}`。
创建 expectedRevision=0；PUT 使用当前定义版本，Job 为 configRevision。
定义控制同时检查 expectedRevision 和 expectedStateRevision；DELETE 的 JSON 体为
`{expectedRevision,expectedStateRevision,requestKey}`，只退休，不清理物理资源。
Run 控制检查 expectedStateRevision；run-again/clone-and-run 额外检查 expectedRevision。
Clone metadata overrides 仅接受 name/description，不自动复制/激活原周期来源。

所有成功写返回 WP01 operation envelope。重复创建完成后返回 200 与原 operationId；
首次定义创建返回 201；后台准入/控制返回 202。accepted 不是效果成功。
异步失败保存原 operationId、结构化 error 和 result.runState；失败 operation
终态不会被后续显式 Retry 的成功覆盖。unknown 保留原身份查询。
forbid overlap 形成持久 skipped admission，不创建第二 Run；queue/parallel 使用
同一 Job 的 maxActive/maxPending 额度；uncertain 占用 active 容量，后续队列不越过
未知效果。重载后的排序按 createdAt，而非序列化 map key。列表 cursor 绑定 principal/profile/资源种类。

## 持久化与内核边界

生产 lifespan 通过 `final_service.bind` 绑定 `app.state.job_final_service` 与
`automation.final_jobs`，启动同一个 consumer，并在 teardown 先关闭它。
临时测试根可调用同一 bind，不需要启动完整 Pan lifespan 或占用监听端口。

当前 profile 的 `job-final/event-creators/creators.sqlite3` 是事务边界：
WP04 Creator/composition 表与 canonical definition、Job aggregate、operation、
authority、Event subscription receipt 表共存，使用 synchronous=FULL。
CreatorStore.transaction 允许线程内借用事务；内层 Creator/composition 调用不能
提前提交。配置 CAS、幂等回执和 activation 在提交前均不可被 consumer 观察。
写入失败整体回滚，重试使用原 requestKey。

`FinalRuntime` 的 store port 直接读写上述同一 Job aggregate；Run、Step、Attempt、
Effect、状态迁移、fence 和 outbox 使用 WP02 Ledger，没有第二 Job 创建/重试宿主。
requestKey 按可信 principal/profile/operation 唯一，payload digest 含目标与完整请求。
同 key 异内容返回 409；replay 在 CAS 前查原收据。Run again 新 Run；Retry 保留
原冻结计划/Run/Step/effectKey，只增失败步骤 Attempt；Clone 经 WP04 composition
activation 后创建新 Job 和一个显式手动 Run。

WP03 的 automation inbox 会冻结 canonical Trigger target，交给 TriggerAdmissionPort，
只做准入并在 automation ledger 保存稳定 admission 投影。Event/Trigger 唯一键不含
revision；投影失败重试查询同一 canonical receipt，不重复建 Run。WP04 EventBus 同样
保存发布时的订阅快照；新 Trigger 不追溯消费旧 Event。筛选/State 条件复用现有 evaluator。
Creator 权限在 occurrence 预留和 publication 前复查；计数/skip/补发仍归 WP04 provider。

效果交给 WP05 TypedExecutor。产品内置 process、session-message、session-broadcast
Action 为 immutable published 定义；channel Action 仅在 host 绑定 channel provider 时
发布。每一步前查当前 Action enabled、Agent job.execute、system Action 的
action.manageSystemActions 及授权 revision；任意 high_risk 继续拒绝。
Job retire/disable 阻新准入，既有 Run 继续使用冻结计划；Job/Run pause 在步骤边界等待，
不伪装 OS suspend。取消已开始的效果先等待原 receipt；accepted 不表示已停止外部效果。

host 丢失活 Attempt 时保留 uncertain/原 effect 和 outbox，不自动重放。Retry 拒绝
unknown/partial、成功效果和缺少必要 cleanup proof 的重投；快照不在也不能重建重试。
手动恢复与原身份查询和新建 Run 分开。

## Authorization 与 Cookie

复用现有 profile-wide User/Agent 矩阵，不新增 Session ACL。
CanonicalUserAuth 对旧四行权限文档仅作读取时 upcast，保留原 grants/revision/bytes；
新增 eventCreator 的 read/create/updateConfig/lifecycle/delete 缺失时均为 false。
权限写入仍须 User 与 CAS。旧 handler 与 authorization.object_path 白名单未删除。

Bearer 使用现有 UserAuth session；`pan_user` Cookie 接受同一种 session token。
Cookie 写必须带与请求 URL scheme/host/port 一致的 Origin，并拒绝 cross-site；
显式无效 Bearer 不回退到 Cookie。客户端自报 source/user/system/header 不构成身份。
本包未新增 Cookie 签发端点，也未验证浏览器登录后的 Cookie 签发/持久化体验。
