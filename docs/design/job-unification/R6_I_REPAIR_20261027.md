## Attempt 的创建边界

`FinalService._drive_run` 在既有 canonical writer transaction 内取当前持有的
`OwnerFence.token[0]`，传入 `Ledger.begin_attempt(owner_epoch=...)`。Ledger 在改变
Step、分配 Attempt 之前检查正整数 epoch、拒绝复用已存在的 attemptId，然后把该
epoch 写入需要校验和持久化的记录。传给 executor 的完整 Attempt 与持久记录一致。
取消在返回对象上另行改 epoch 的做法。`finish_attempt` 原 epoch/generation/active
状态 fence 未改；重试生成新 Attempt，原 Attempt 和 effectKey 语义保持。

生产调用方只有三个：canonical `_drive_run` 和 `action_runtime.py` 的两个旧 aggregate
调用。后两者保留默认 epoch 1，运行仍受原 legacy pass/writer 限制，不能借此越过
已建立 canonical owner；独立 executor/runner 消费冻结的 Attempt/fence，不创建另一个
Job/Run/Attempt。没有 owner 记录的离线/独立 aggregate 可保留原 bootstrap epoch 1；
已有 owner 的 handle 若未持锁，writer 原门禁先拒绝，不能通过默认值写入。

恢复不改写旧 Attempt 的 owner。丢失的 in-flight effect 仍进入原 unknown/reconcile
路径，按原 effect identity 查询，不根据新 epoch 再发一次。独立执行协议、generation、
owner 文件锁、late receipt 拒绝、unknown 不重发均保持原实现。

## Scheduler 管理 API

旧 `/api/scheduler/event-sources` GET 仅供明确历史读取；旧 POST/PUT/DELETE 在
`bac726cf` 已认证后返回 410。它们不是 canonical 来源管理接口。当前 Automation 页面
改用 `/api/event-creators`、`/api/triggers`、`/api/jobs`，不再请求旧 source 列表或 writer。
来源实例不因订阅数复制，不按配置内容自动合并，不改原 pending adoption port。

新增的两个读端点均在通用 object route 前注册，`/api/final` 继续作为 deprecated 同处理器别名：

| 入口 | 返回值与授权 |
|---|---|
| `GET /api/event-creators/providers` | 当前注册 Scheduler provider 的完整 providerRef/configSchemaRef、eventTypes、capabilities、config JSON Schema；要求 `eventCreator.read` |
| `GET /api/event-creators/{creator_id}/references` | 非 retired Trigger 的显式 IDs 或匹配 registeredType 订阅，包含 Trigger revision/stateRevision、Job/configRevision、enabled、selector；稳定排序和 referenceDigest。要求 EventCreator、Trigger、Job 三项 read，避免跨对象元数据泄漏 |

以下为兼容现有 canonical write envelope 的可选审阅字段，旧调用方的其它未知字段仍拒绝：

| 写入口 | 附加字段 | 检查与幂等 |
|---|---|---|
| Creator PUT | `expectedReferences: string` | 在同一 writer transaction 比较当前引用 digest；内容 CAS 继续使用 expectedRevision。附加字段进入 request digest |
| Creator lifecycle | `parameters.expectedReferences` | 原 expectedRevision/stateRevision 均必需；引用改变返回 reference_conflict |
| Creator DELETE | `expectedReferences` | 转为原 retire 操作的 parameters；UI 使用该字段时，enabled 或仍有订阅均拒绝。retire 保留历史，不物理删除 |
| Trigger POST/PUT | `expectedCreatorRevisions: {creatorId: revision}` | supplied map 必须恰好覆盖 ids selector 的全部 ID，revision 必须为实际整数且一致；registeredType 对应空 map。全部检查先于写入；失败无半条订阅 |

本轮 UI 始终携带上述审阅字段；共享来源保存前明确列出影响对象并要求 review。
API 沿现有 User Bearer/cookie same-origin 与可信 Agent grants，不从 payload 获取权限。
新 metadata API 不授予执行权。新 source create 保持 draft，启用是独立显式 lifecycle
操作；若配置已提交而后一步失去回执，只能先查原 operationId/requestKey。

## React 数据与交互

- workspace 对 native 集合逐页读取并拒绝重复 cursor；只把 time/scheduler Creator 放入
  Scheduler 列表。系统/plugin event definitions 与 diagnostics 继续只读展示。
- EventRegister 保留 name/description、完整 config JSON、provider/schema refs 和 eventTypes。
  不把 runtime cursor/producedCount 作为可编辑配置。支持 once、十进制 interval、anchor、
  weekly、cron、IANA/fixed-offset timezone、DST、misfire/grace/pause、driveLimit 全字段。
- Job/Trigger 页复用已有 canonical 定义/Run 管理组件：Job steps 固定 Action ref 与绑定，
  Trigger 只持有 targetJobId、creatorSelector、eventTypes、condition/filter/arguments。
  完整定义以 JSON 编辑，新增 native Job/source 选择器及显式 source revision review；不把
  旧 compose/direct Action 请求换一个 URL 后继续发送旧字段。旧按钮布局不是新的模型契约。
- 配置与 lifecycle 分开提交；定义冲突保留本地（包括无效 JSON）并可显式比较、rebase 或
  加载服务器定义。source 操作 unknown/5xx 禁止重发，查询原操作；4xx 不清空草稿。
- 三个子页保留同时打开的草稿，共用 route/unload guard；请求中的重复 submit 被同步锁拒绝。
  全局 Refresh 同时更新 source refs 与 native Job/Trigger 列表，不覆盖正在编辑的草稿。
- 删除共享来源需要先显式解除订阅并停用来源；不自动删除 Job/Trigger，不复制原 source，
  retire 后 canonical GET 和原历史读取继续有效。原来源的 source_links/requests 仍按
  P22 证据保留，不经这个新建来源 UI 自动 adopt。

本次保留既有 Actions/Pause Template 管理入口；旧 Action registry 到 native immutable
Action publication 的全产品接入不由本次 source UI 浏览器用例证明。浏览器用例使用原生
产品 Action 与自有 RecordingProvider，不连接真实 provider。
