## 现有单一证明链

- `packages/core/cli.py`：`start_lock` 保护 CLI start/debug；exit/restart 使用
  `lifecycle()`，传 running offline/preserve，等待原 effect 的 canonical receipt；
  status 独立核对 PID/birth/HTTP。本片将 supervisor 的内部 start 纳入同一 start lock。
- `packages/core/lifecycle_action.py`：固定 `system_main_lifecycle`，原 requestId
  派生 job/run/step/attempt/effect；不是另建 ledger。服务路由的 requestId 与
  通用 Action requestKey 不可混用：此 HTTP 路由不接受 requestKey 字段，而是从
  root/port/operation/PID/birth 派生 requestId。查询须保留原 requestId/effectId，
  不生成新键重试。（R2 修正首片对该入口键名的不准确描述。）
- `packages/web/server.py`：canonical preparation 冻结 running snapshot/策略，
  关闭 Worker gate，等待 Worker shutdown；单飞/原 receipt 查询保留。
- `packages/core/main_lifecycle.py`：授权、capability、root/port/PID/birth 检查；
  `stopping` 事务关闭取消窗口；stop → offline proof → start → 新 listener/root/
  birth/HTTP ready proof。停止或启动效果中断保持 unknown，不自动重放。
- `packages/jobs/independent_executor.py`：原 ExecutionStore/claim/attempt fence；
  `packages/core/platform/execution_host.py` 的短命 bootstrap 等待 retained Popen
  exit receipt，再允许独立 supervisor 效果；不以 setsid 单独证明完成。
- `packages/core/launcher.py`：process.json、解释器选择、入口/root marker、
  listener owner、ready、graceful shutdown、Windows 经复核的 taskkill fallback。

## 本片源码变化

`packages/core/platform/service_process.py` 是薄 OS 边界：Windows Popen 参数原样
保留；POSIX spawn 复用现有 ProcessOwner（Linux starttime/boot_id，Darwin
native uniqueid/boot UUID），持久 `processIdentity` 附加到原 process.json 的 main
记录。POSIX 服务 stdin 断开、输出经已有 console shim 落日志。恢复终止使用同一
ProcessOwner.recover，缺身份/身份不符/残留/unknown 都不返回 stopped=true。
授权、running 策略、operation receipt、取消和恢复逻辑均留在原链路。

这没有新增 API、数据库或第二个恢复引擎。新增 process.json main.processIdentity
为附加字段，旧 Windows 记录不变；旧 POSIX 无强身份记录不能获得组终止权限。

## 对等矩阵与官方依据

| 分项 | 用户功能对等判断 | 安全保证对等判断 | OS 专有不可等同 | 所需证据 / 当前边界 |
|---|---|---|---|---|
| PTY | 输入/输出、resize、交互式 TUI 可分别实现，尚无 Pan POSIX backend | PTY 本身不证明树所有权、清理或隔离 | ConPTY handle 与 POSIX master/slave/controlling terminal 不同 | 真实 Linux/macOS TUI、resize、UTF-8、信号、断线和清理；当前 capability=false |
| detach | 宿主退出后保留、重连同一终端可设计 | 需持久 owner/IPC、原终端身份、认证和残留证明；setsid 不足 | Windows Job/命名管道不能直接等同 PGID/Unix socket | 主宿主崩溃、leader 退出、重连、stale owner、权限负控；当前 false |
| Rewind | 依赖供应商的交互流程，尚不能确认功能对等 | 不能把脚本输入当成原历史已回滚 | 当前 cbc ConPTY 菜单自动化依赖 Windows 实现 | 目标版本原生 cbc 菜单、原会话身份与历史效果、取消/超时；当前 false |
| service.lifecycle | R2 Windows 自有真实 main/CLI/HTTP start/exit/restart/status 已验证；POSIX 整链等待目标运行 | 原 receipt、取消 fence、birth/root/listener/HTTP 证明链复用；POSIX 原组/已观察成员只读证明不等于 containment | setsid 不提供 systemd cgroup，也不提供 launchd 的系统/登录会话管理 | Windows 原生 trial 通过；Linux/macOS workflow 待 MA 接入；登出/开机自启归后续安装分项；POSIX false |
| secretStore | Keychain / Secret Service 可作为候选存储接口 | 不预设与 DPAPI 相同的用户绑定、解锁、无人值守和恢复保证 | Windows DPAPI、macOS Keychain、Linux D-Bus collection/session 是不同机制 | 真实 headless/locked/unavailable/权限拒绝、不落明文、备份恢复；当前 false |
| 安装 | 可分别提供可执行 CLI、解释器/依赖、配置和卸载 | 用户/系统级权限、路径和启动注册需独立验证 | systemd user unit 与 launchd Agent/Daemon 具有不同的会话/安装语义 | 干净目标系统 install/start/status/restart/exit/uninstall；不触碰用户既有 profile |
| process.hiddenDesktop | 无窗口运行可实现；Windows 私有 desktop 功能不能直接承诺 POSIX 对等 | 私有 desktop + restricted token + Job 属性没有已证明的 POSIX 同构保证 | 重定向输出、setsid、无 DISPLAY 都不能替代桌面 ACL/令牌隔离 | 保持 false；由 MA 决定安全目标及独立 sandbox 方案，不复用 hiddenDesktop 名称宣称等价 |

官方资料（2026-11-03 查询；判断为依据这些机制的工程推论）：

- [Python subprocess](https://docs.python.org/3/library/subprocess.html)：
  start_new_session 在 POSIX 子进程 exec 前调用 setsid；不提供服务管理的证明。
- [Linux devpts](https://www.kernel.org/doc/html/latest/filesystems/devpts.html)：
  master/slave 节点和权限与挂载相关；不能从 PTY 存在推出 ownership。
- [systemd.kill](https://www.freedesktop.org/software/systemd/man/249/systemd.kill.html)：
  control-group/mixed、终止超时与剩余进程升级信号有具体策略。
- [Apple launchd jobs](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html)：
  launchd 管理的 daemon 不应自行 setsid；[系统与用户服务](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/DesigningDaemons.html)
  区分系统 daemon 与每用户会话 agent。
- [Apple Keychain services](https://developer.apple.com/documentation/security/keychain-services)：
  提供加密 keychain 存储机制。
- [Secret Service 解锁](https://specifications.freedesktop.org/secret-service/latest/unlocking.html)：
  collection 解锁有其会话和交互语义，不能假定 headless 永远可用。
- [Microsoft desktop/window station](https://learn.microsoft.com/en-us/windows/win32/winstation/about-window-stations-and-desktops)、
  [restricted tokens](https://github.com/MicrosoftDocs/win32/blob/docs/desktop-src/SecAuthZ/restricted-tokens.md)、
  [Job objects](https://github.com/MicrosoftDocs/win32/blob/docs/desktop-src/ProcThread/job-objects.md)：
  分别定义 UI 对象、安全访问限制和进程组管理，不能用无窗口这一外观替代。
