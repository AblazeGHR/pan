# 统一服务端消息队列改动计划

状态：已实现核心路径，持续验证中

日期：2026-09-02

## 1. 目标

将前端发送、Agent 任务、报告和 QQ 提醒统一到 `Session.queue_pending`。
该字段是唯一持久化真源；`Worker.pending_signal` 只负责唤醒消费者，不携带
正文、来源身份或消费决定。

用户消息无论 Worker 当前是否运行，都先由服务端持久化为 task queue item，
再返回“已入队”。Worker 忙时不会中断当前任务，也不会把新消息直接写进 CLI
stdin。前端队列面板以服务端 `GET /api/sessions/{id}/queue` 为权威镜像。

## 2. 队列项模型

新 task 使用服务端生成的稳定 `id`，并保存类型、来源、正文、序号和幂等键：

```json
{
  "type": "task",
  "id": "<uuid>",
  "source": "user",
  "text": "请检查这个项目",
  "seq": 12,
  "taskId": null,
  "clientMessageId": "browser-uuid",
  "deliveryState": "queued"
}
```

来源和类型分开：`user/agent/system_prompt` 可以是 task 来源，`report` 为
报告来源，QQ 为 `type=qq`。报告、notice、QQ 新行也有稳定 id；旧行在 Worker
恢复或离线迁移脚本运行时补齐。

## 3. 消费顺序和 hand-off

统一消费者每次只读取 durable FIFO 队头：

```text
queue_pending 队头
  → queued → reserved（持久化）
  → writing（运行态细化）
  → provider hand-off 成功
  → sent_to_cli（持久化标记）→ 删除该 queue item
```

- task 是一个 CLI hand-off。
- 连续的 report/QQ 行合成一个批次；中间遇到 task 就停止，批次全出或全回。
- stream 的 hand-off 是完整序列化字节写入 CLI stdin 并成功 `write + drain`。
- one-shot 的 hand-off 是使用现有 adapter argv 协议成功创建携带完整请求的 CLI
  进程，不改为 stdin。
- 成功 hand-off 后不等待业务 result、history、provider 退出或前端事件才删队列。
- hand-off 前取消、Worker 崩溃、进程重启或确认写失败，都将原 item 退回 queued，
  带有界指数退避；允许 CLI 已收到而 Pan 尚未落盘的窄重复窗口。

只有一个 Worker consumer 处理一个 Session，信号重复只会触发再次扫描，不会产生
第二个并发消费者或绕过队头。

## 4. API/UI

### 4.1 用户发送

React 输入框始终调用 `/api/send`，带 `clientMessageId`。服务端对该键做持久
幂等检查，返回队列确认；重连重发命中原 queue item，不创建第二条。WebSocket
`user_inject` 保留为兼容接口，但同样只调用服务端 durable send，不允许正文进入
`pending_signal`。

### 4.2 队列面板

面板分开标识旧客户端/断网 local outbox 与服务端 FIFO，但正常输入不再落 local
outbox。服务端的 `reserved/writing/sent_to_cli` 行不显示为待发送，queued 行仍
显示；所以 Worker 当前任务运行时，新入队消息不会从面板立即消失。

queued 项可删除或按现有 task 槽位重排；retry 使用同一 `queueItemId` 清除退避并
唤醒原 receipt，不复制正文。交接中的行不允许删除或越过。

## 5. 旧数据迁移

运行时迁移与命令行脚本共用同一逻辑：

```powershell
python scripts/migrate_queue_delivery.py --session-dir <data/sessions> --apply
```

脚本默认 dry-run；`--apply` 会先把每个变更的 `.json` 和对应 history JSONL
复制到带时间戳的 `queue-migration-backups`，再原子保存。迁移规则：

- 无 type 的 text 行 → `type=task`、默认 `source=user`、补 id/seq/taskId；
- 无 type 的 result 行 → report；旧 QQ/notice/report 行补 source/id；
- `reserved/writing/in_flight/write_failed/unknown_after_crash` → queued + backoff；
- `sent_to_cli` → 删除，因为它已证明完成 CLI hand-off；
- 已迁移文件再次运行不产生新 id、不再次改写队列。

新 `Session` 保留旧实现曾写入的 `queue_delivery_ledger` 和 `queue_revision` 字段，
作为兼容元数据加载并持久化；它们不是第二条消息队列。

## 6. 验收范围

相关回归测试覆盖：

- running 状态下追加消息仍在服务端 FIFO 队列；
- stream 写入边界、one-shot 创建边界；
- hand-off 成功出队；写失败、取消和重启恢复原 item；
- FIFO 不跳过队头；连续报告/QQ 批量全出全回；
- `clientMessageId`/`taskId` 幂等与原 receipt retry；
- GET 面板隐藏内部 hand-off 状态；
- 旧 JSON 加载、运行时迁移、脚本备份和重复运行幂等。
