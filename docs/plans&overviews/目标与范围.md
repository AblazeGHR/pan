# 目标与范围

> 讨论顺序第 1 步：方向和边界。

---

## 1. 愿景

CLIConductor 是一个让用户**全方位、可远程地管理和对话本地 Agent CLI** 的工具平台。通过 Meta-Agent 实现多 Worker 的高级别调度，让 Agent 擅于闯入各个场景（开发、社交、日程、自动化……）。

**Phase 2 目标**：Pan 不只为自家 Worker 服务，还能作为"工具底座"被外部领域项目（首例：[RuleWhisper](https://github.com/AblazeGHR/RuleWhisper)）接入——外部项目提供 HTTP API / MCP Server，Pan 的 QQ Bot 和 Worker 承担消息入口和推理调度。

| 借鉴项目 | 借鉴点 |
|----------|--------|
| OpenClaw / Claw | 本地化 + 路由方案；AI 闯入本地管理与社交平台 |
| Tutti | 跨 CLI 工作；统一界面和 Adapter 设计 |

## 2. 边界

| 做 | 不做 |
|----|------|
| CLI Agent 调度器 | 不自己实现 AI Agent |
| 进程管理 + 消息路由 + 通道适配 | 不管理 Worker 的工作目录内容（git、文件编辑） |
| Session 可检索（摘要/标签/搜索） | 不做通用知识库 |
| MCP Server 配置透传（工具层注入） | 不实现 MCP 协议本身，不替换 Worker 通信协议 |

## 3. 核心场景（按优先级）

| 优先级 | 场景 |
|--------|------|
| P0 | Web Dashboard 远程管理、Meta-Agent 调度、QQ Bot 通道 |
| P1 | 多 CLI 适配（cbc / claude-cli / gemini-cli）、Worker 快速包装为专用 Agent、远程访问 |
| P2 | 自动化流水线（定时/事件驱动） |
| P2 | 外部项目接入（通用 Manifest Loader + QQ 命令路由），首例：RuleWhisper |

## 4. 定位结论

| 决策 | 结论 |
|------|------|
| 与 CLI 工具关系 | 多 CLI 支持，Adapter 模式是核心设计 |
| QQ Bridge | 一等通道，与 Dashboard 同等重要 |
| 多用户 | 暂不，但架构预留扩展点 |
| Session 数据模型 | cbc 专有字段移入 `adapter_config`，Session 只保留通用字段 |
| 通道可见性 | 支持隔离能力。最高权限用户拥有一切数据的可视权和交互权。受限通道（如对外 QQBot）可限制其 Worker 权限（不可 spawn、不可创建 Session、不可访问工作目录外） |
| 远程认证 | 需要认证 + 来源辨析（如按 QQ 号区分用户 vs 外人） |
| 事件协议版本化 | 留到模块设计阶段定义 |

## 5. 模块拆分

### 5.1 原则

1. 每个模块独立开发、独立测试、独立部署
2. 模块间通过 HTTP/WS 接口通信，不 import 彼此内部实现
3. Core 最小化：只做进程管理 + 消息路由
4. 通道是插件

### 5.3 模块职责

| 模块 | 职责 | 对 Core 的依赖 | Phase 2 现状 |
|------|------|---------------|-------------|
| **Core** | 进程生命周期、Session 持久化（原始数据）、事件路由、Adapter 注册、Worker Profile 管理 | — | ✅ 已清洁，API 稳定 |
| **Memory** | Session 摘要/标签/搜索、跨 Session 知识沉淀、用户偏好记忆 | Core WS 事件流 | ✅ 已落地（`core/memory/`，feature/memory 已合入 main） |
| **Adapters** | 每种 CLI 一个 adapter（启动参数、事件解析、消息编码）。通过 manifest 注入 MCP Server 配置到 spawn 参数 | Core 协议 | ✅ cbc/kimi 已实现，MCP 透传已实现（`--mcp-config` + one-shot 模式） |
| **WebChannel** | HTTP 服务 + Dashboard 前端 + Meta-Agent WS | Core HTTP/WS | ✅ Vite+React 前端已迁移，支持 coexist/react/legacy 模式 |
| **QQChannel** | QQ Bot，将 QQ 消息转为 Core 任务。已支持 user/group 两级 Session 绑定（`_ensure_session` 按 scope 区分）；确定性前缀命令路由（manifest command_routes）**尚未实现** | Core HTTP/WS | ✅ 已抽离，群级绑定已实现，前缀路由待做 |
| **Remote** | 远程隧道 + 认证 + 来源辨析 | 通道层 | ✅ Cloudflare Tunnel 已实现 |
| **SDK** | Worker 快速包装为专用 Agent | Core HTTP/WS | ⏳ 待启动 |

**Core 与 Memory 的分界**：Core 只存原始数据（history 数组），不索引不加工。Memory 监听 Core 事件流，生成摘要/标签/知识，暴露自己的 API。

### 5.4 模块通信

所有模块通过 Core 暴露的 HTTP/WS 协议通信，不 import Core 内部实现。每个通道是 Core 的一个"客户端"。

```
# Session 管理
GET    /api/sessions                   → 列举所有 Session
POST   /api/sessions                   → 创建 Session
GET    /api/sessions/{id}              → 获取 Session 详情
GET    /api/sessions/{id}/history      → 获取历史消息
PATCH  /api/sessions/{id}              → 更新 Session
POST   /api/sessions/{id}/rename       → 重命名
POST   /api/sessions/{id}/branch       → 分支
DELETE /api/sessions/{id}              → 删除
POST   /api/sessions/batch-delete      → 批量删除

# Worker 管理
POST   /api/spawn                      → 启动 Worker
POST   /api/task                       → 发任务
POST   /api/kill/{worker_id}           → 停止 Worker
GET    /api/list                        → 列举活跃 Worker
POST   /api/worker/{id}/restart        → 重启
POST   /api/worker/{id}/settings       → 配置
POST   /api/worker/{id}/rename         → 重命名
POST   /api/worker/{id}/branch         → 分支
POST   /api/worker/{id}/interrupt      → 中断
POST   /api/worker/{id}/takeover       → 接管终端

# Adapter / 模型
GET    /api/adapters                   → 列举 Adapter
GET    /api/models                     → 模型列表

# CBC 导入
GET    /api/cbc/projects

POST   /api/cbc/sessions/import

# Kimi 导入
GET    /api/kimi/workspaces

POST   /api/kimi/sessions/import

# WebSocket
WS   /ws                               → 事件流（广播）

# Character / Memory（feature/memory 合入后新增）
GET    /api/characters/profiles        → 列出 Profile
```

### 5.5 跨平台

跨平台改造已在 Phase 2 早期完成：`worker.py` 使用 `psutil` 替代 `taskkill`，终端接管使用 `platform_opener()` 封装，CLI 路径使用 `shutil.which()` 查找。

### 5.6 外部项目接入模式

Pan 作为"工具底座"，外部领域项目（如 RuleWhisper）通过两种方式接入：

1. **HTTP API 前缀路由**：外部项目的 manifest.json 声明 `command_routes`，Pan 的 QQ Bot 插件遍历并匹配前缀，命中后直发 HTTP API，不创建 Worker。
2. **MCP Server 透传**：外部项目的 manifest.json 声明 `mcp_servers` 和 `profiles`（character 模板），Pan 的通用 Manifest Loader 加载并合并到全局池。Worker spawn 时注入 `--mcp-config`。

外部项目**不 import Pan Core 内部**，仅通过 HTTP/WS 或 MCP 协议与 Pan 通信。
