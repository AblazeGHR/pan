# 功能整合与 practical 推进门禁

当前授权：功能与修复经 MA 验收后逐步进入 main，push 精确 SHA 运行 CI；所有目标功能整合且最终门禁通过后，一次性推进 practical。分支推进不等于服务重启或发布。

## 路线与冻结

- CI 已有失败修复与 Locker 产品接入、系统字段闭环并行；不把未交付实现纳入候选。
- MA 阅读实际 diff 和证据，针对风险验证；接受候选后依次整合 main，处理语义冲突并 push。
- 中间 CI 用于尽早发现问题，不能代表最终门禁。输入收齐后冻结完整 main SHA，再核验该 SHA 的 Python 3.12/3.14 双矩阵、前端构建和组合冒烟。
- 冻结后发生影响行为的修改，更新冻结 SHA，并补跑相关门禁；不能沿用旧 SHA 通过结论。

## practical 前必须完成

1. 确认 main 含全部已接受功能及修复，工作树中用户修改完整保留；核对 practical 当前 HEAD、状态和进程归属，不覆盖 dirty 文件。
2. 获取 practical 数据只读私有副本，记录采样范围和一致性限制；只在隔离环境运行实际 loader/迁移。禁止副本自动恢复真实 Job、Worker、QQ/provider 或外部副作用。
3. 核对 Session 元数据/history、Queue 原 ID 与投递账本、旧 Job/Template/Action、QQ/Agent Inbox/User Locker，以及 Event/Trigger/Run/Attempt 存储。不存在的存储单列为空初始化，不能声称迁移通过。
4. 验证重复迁移幂等、未知字段保留、缺引用可见、旧配置不会意外启用、unknown/uncertain 不自动重投、快照终态清理、已读与卡片答复/拒收/删除的兼容边界。
5. 在最终候选验证 Locker 真实 API/通知/choice 执行与可信绑定、系统字段 Event 到 Action、Job 及报告诊断共存；浏览器检查桌面与320/390px，附件与正文复用路径。
6. 核验最终 SHA 远端双矩阵完整日志/JUnit，全部失败身份有去向，skip无未解释增加。区分本地与远端结论，不以重跑掩盖未定位的重复故障。
7. 写明停旧 writer、备份、升级、失败恢复与回退限制。新旧 writer 不共同写迁移后的 profile；不可逆变化不能只退代码。
8. 全部门禁通过后，重新核对 refs 和数据变更，按授权一次性推进 practical；执行必要构建并报告生效条件。服务重启、真实数据原地迁移和发布按适用授权分别执行。

源数据不得进入Git。审计仅保存脱敏统计、哈希、命令、受测SHA和证据入口。任何失败必须有下一步，不将候选交付等同整体完成。
