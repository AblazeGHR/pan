# CP-X5 POSIX PTY：backend 候选与宿主抽取边界

基线 31304d443c7c7378208690a345caa7f15afac54a。独立分支 feat/cp-x5-pty-20261104；原 service 分支保留。最高优先 service.lifecycle 已签收的受限输入不重跑独立 service CI；本片对 ProcessOwner 受影响接口做组合契约。

## 已实施的独立部分

- terminal/backend_posix.py 实现已有 PtyBackend + TreeGuard 接口，复用 PosixProcessOwner/PtyRuntime，无第二 registry、ledger、输出账本或 attachment 系统。
- openpty 得到 master/slave；ProcessOwner 仍在 exec 前建立独立 session/group，取得原生 birth/boot 身份和 retained Popen。POSIX owner 新增可选 pass_fds（默认空，不改变旧 spawn）。
- 全新 Python bootstrap 获取 TIOCSCTTY/tcsetpgrp 后通过短命 socketpair 等待原 owner 强身份核验；获准后同 PID exec，控制 FD 的 CLOEXEC EOF/显式错误作为启动握手。不使用多线程宿主 preexec_fn/forkpty。socketpair 不是持久 IPC/重连入口。
- contracts.ProcessIdentity 新增可选 native_identity 精确 tuple；Windows FILETIME 路径和无字段的序列化保持原样。不得把 ticks/uniqueid 转成假 FILETIME 或弱浮点时间。
- nonblocking master 的有界读、partial write、resize；实际 syscall 与 close 互斥，select 等待不阻止其它输入。Linux EIO 需同时有内核 HUP 才当 peer EOF，否则错误不冒充输出完整。
- 原 ProcessOwner 核验与读组/已观察成员证明用于 close；权限/身份/残留未知保留 owner/FD，不按 stale PGID 杀。强 identity 失败走原 owner spawn-abort；握手失败明确清理，清理未知异常携带 pty_backend 资源属主。
- 无 DetachHandler；runtime.detach 明确拒绝。普通浏览器 attachment 断线并不代表 durable detach。

## 具体耦合与最小下一抽取

1. TerminalService._start 在 _spawn 前调用 _store，默认 SecretStore 是 Windows DPAPI；后续 complete_bootstrap/RunnerClient 必须通过 Windows 端点身份核验。不能假造秘密或把本机空 token 当认证等价。
2. TerminalRunner._bootstrap 固定 SecretStore + win_pipe.current_process_identity，_prepare 固定 win_pipe.PipeServer；_spawn_backend 固定 ConPtyBackend，_build_runtime 固定 job-object。只换 backend 工厂不能获得产品 Terminal。
3. HeadlessEmulator.__init__ 明确 Windows-only，_spawn_and_handshake 仍直接 JobObjectGuard；未经真实宿主测试不能称为完整 authoritative TUI snapshot。
4. packages/web/terminal_api.py build_runtime 还有非 Windows gate；现有 REST/WS origin/Host/认证、attachments/终端 Session 绑定不可绕过。

最小方案为从 TerminalService 抽取一个非 durable 本机 runtime 装配接口，默认 Windows 仍走原 RunnerClient，POSIX 同服务进程持有原 PtyRuntime/OutputLog/AttachmentRegistry/TerminalRegistry；不落持久 IPC secret，不承诺服务退出后重连。需要明确服务崩溃后的残留状态及 reconcile 规则，不能把纯 pipe 当 PTY。另一条 durable 独立 runner 路线涉及 POSIX endpoint peer identity、秘密存储和 emulator 宿主，属于后续授权分项。本候选先交 MA 审阅该具体抽取，不假称整链完成。

路径所有权建议：本 TA 当前串行持有 terminal/backend_posix.py、pty_bootstrap_posix.py、contracts.py 可选身份字段、process_posix.py 可选继承 FD、专用 tests/workflow。下一装配片持有 terminal/service.py + 新薄 host adapter + web/terminal_api.py gate，并复用原 registry/attachments/output；emulator 宿主另片；durable IPC/secretStore 与 Rewind 后续分开。共享 capability 注册表由 MA 串行协调。

## 官方机制依据

- Python [pty](https://docs.python.org/3/library/pty.html)：master/slave 真 PTY，macOS fork 与高层 API 混用有安全限制。
- Python [subprocess](https://docs.python.org/3/library/subprocess.html)：多线程程序不安全使用 preexec_fn；start_new_session 与 pass_fds 提供独立会话及显式 FD 继承。
- Linux 项目 [TIOCSCTTY](https://www.man7.org/linux/man-pages/man2/TIOCSCTTY.2const.html)：调用者须为无控制终端的 session leader，本实现 arg=0，不窃取其它 session 的 tty。
- Linux 项目 [TIOCSWINSZ](https://www.man7.org/linux/man-pages/man2/TIOCSWINSZ.2const.html)：窗口改变向 foreground group 发 SIGWINCH。macOS 机制不由 Linux 文档代证，依实际目标契约。
