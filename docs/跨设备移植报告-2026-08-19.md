# Pan 跨设备（Windows）移植报告

日期：2026-08-19
范围：D:/project/Pan 全仓（packages/、scripts/、tests/、根配置文件、data/）
目标：在另一台 Windows 机器上运行同一项目（含整体拷贝目录 与 git clone 两种迁移方式）。

---

## 一、结论摘要

Pan **自身运行数据**（会话、角色、日志、workdirs、PID）全部相对仓库根解析，整体拷贝即可迁移。
真正阻碍移植的是三类内容：

1. **机器专属绝对路径 + 用户名**：config.json、.mcp.json、data/mcp-configs/ 运行时产物里写死了 `D:/project/...`、`C:\Users\14709\...`；
2. **仓库外兄弟项目引用**：依赖 `D:/project/ai_coc`（插件 manifest + MCP rulewhisper）；
3. **用户目录 transcript 依赖**：cbc/kimi 的历史会话存在 `~/.codebuddy/projects` 与 `~/.kimi-code`，目录名按"绝对路径脱敏"生成，换路径后旧会话全部失联。

另有若干**端口默认值硬编码**与 **CWD 依赖**，属于次要问题。

### 两种迁移方式的关键差异

| 迁移方式 | 硬编码影响 |
|---|---|
| **整体拷贝目录** | config.json / .mcp.json / data/mcp-configs 里的绝对路径直接失效，必须改 |
| **git clone**（剔除 .gitignore 内容） | 这些文件本就不在版本库、不会带过去，**无需清理**；但残留的是**代码级**硬编码（见 §二·改） |

> 走 git clone 时，config.json / .mcp.json / data/ / .venv 都不会来，新机需按 config.example.json 重建 config.json、重建 .mcp.json、创建 venv。

1. ✅ **统一端口默认值**（2026-08-19 已完成）：全仓以 8768 为标准。`config.py`、`main.py`、`qq/plugin.py`、`remote/main.py`、`config.example.json`、`vite.config.ts`、`package.json`、`start_cf.ps1` 的 8767 全部改为 8768；`mcp/server.py`、`monitor_workers.py` 保持 8768。

3. **.mcp.json / data/mcp-configs 相对化**：用仓库根推导命令与 cwd（或 `${PAN_ROOT}` 占位符，参考 manifest 已有做法），避免绝对路径。
4. ✅ **CWD 依赖修复**：`manifest_loader.py` 把相对 plugin_manifests rebase 到仓库根，不依赖 CWD（2026-08-22 核对已修复，`REPO_ROOT` 推导）；`server.py` 的 `Path.cwd()` 兜底（import/spawn）待处理。

6. **历史会话迁移**：拷贝 `~/.codebuddy/projects`、`~/.kimi-code`，并保持目标机项目路径与旧机一致（或改脱敏目录名）。
7. **tunnel 凭据**：整体拷贝迁移时带上 `.cloudflared` 目录；否则切 `quick_tunnel: true`。
