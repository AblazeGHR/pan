## 严重（必修）

### 1. 全 API 无鉴权，危险操作可匿名调用

**位置**：`packages/web/server.py` 全局 + `main.py:23-35`

**问题**：所有端点（`/api/fs/*`、`/api/task`、`/api/kill`、`/api/sessions` 删除、character 删除等）无任何认证中间件。`main.py` 仅在非回环绑定打印 WARNING，不拦截。

**影响**：绑定 127.0.0.1 是唯一屏障；多用户机器、DNS rebinding、被 XSS 的浏览器标签页可直接利用。

**修复**：加 shared-secret token（波及 2 前端 + MCP server + WS，需同步）；或至少非回环 host 直接拒绝启动而非告警。

### 2. 绝对 workdir 任意磁盘读写删

**位置**：`packages/web/server.py:225,228-255`

**问题**：`_ALLOWED_WORKDIR_ROOTS` 默认 `None`，`_resolve_workdir` 对绝对路径直接 `mkdir` 返回，无任何限制。结合 `/api/fs/*`（其路径穿越防护正确，但只防「逃出 workdir」不防「workdir 本身是任意目录」），可对磁盘任意目录读写删。

**修复**：默认强制限制在 `WORKDIRS_DIR` 内（或白名单根目录）。

### 3. `_read_stdout` unbound 变量 `s`

**位置**：`packages/core/worker.py:224`

**问题**：`s` 仅在循环内 `is_init_event`/`is_assistant_event`/`is_result_event` 三个分支赋值。若 stdout 为空、或所有行都无法解析/不匹配，循环结束（第 224 行）引用 `s` 抛 `NameError`，reader task 静默崩溃，且第 237 行 `workers.pop` 不执行，留死 worker。

**修复**：循环前 `s = None` 初始化。

### 4. kimi fork 分支失效

**位置**：`packages/core/adapters/kimi/adapter.py:149-167` + `packages/core/worker.py:830-832`

**问题**：kimi 的 `fork_args` 在内部完成文件复制后**返回 `[]`**；而 `branch_worker` 用 `if not extra_args` 判定「不支持 fork」，导致 kimi 分支永远报错「does not support fork」，且已复制出孤儿会话目录。

**修复**：fork_args 返回非空标记，或 `branch_worker` 改用单独的 `supports_fork` 判定。

### 5. WebSocket handler 泄漏 + 重复注册

**位置**：`packages/web/src/hooks/useWebSocket.ts:19-93`

**问题**：`wsClient.on(...)` 返回的注销函数被丢弃，cleanup 返回空函数。Chat→Editor 切换会卸载 ChatView，返回时重新注册整套 handler，事件处理重复累积（重复 addMessage/loadSessions）＋监听器泄漏。

**修复**：保存所有 unsubscribe 并在 cleanup 中调用。

### 6. 草稿保存功能失效（DOM 耦合）

**位置**：`packages/web/src/stores/sessionStore.ts:114-117` + `packages/web/src/components/chat/InputRow.tsx`

**问题**：`selectSession` 用 `document.getElementById('chatInput')` 保存草稿，但 InputRow 的 textarea 无 `id="chatInput"`，该 DOM 读取永远返回 null，草稿保存/恢复实际失效，且 store 与 DOM 耦合。

**修复**：从 store 的 inputDrafts 读写，不碰 DOM。

### 7. embedding API key 片段落库

**位置**：`packages/core/memory/embedder.py:481-482`

**问题**：`_cache_key` 返回 `api_key[-8:]` 作为 `provider_key` 持久化进 `embedding_cache` 表，泄露部分密钥且低熵易碰撞。

**修复**：改为 `sha256(api_key)` 摘要。

## 高（正确性 / 并发）

### 8. 广播并发写竞态

**位置**：`packages/web/server.py:108-122`

**问题**：`broadcast` 对同一 WebSocket 无锁并发 `send_json`（多 worker 广播同时触发），Starlette 非并发安全，易报并发写错误。

**修复**：每连接加锁或串行化发送。

### 9. Session 非原子写 + `_cache` 无锁

**位置**：`packages/core/session.py:191-207`

**问题**：`_save_sync` 用 `write_text` 截断后写入；`save_async` 走 `asyncio.to_thread`，同一会话文件可能被事件循环与线程并发写，产生交错/损坏；`_cache` 字典跨线程无锁读写。

**修复**：临时文件 + `os.replace` 原子写；`_cache` 加锁。

### 10. `load_config()` 热点路径反复读盘

**位置**：`packages/core/adapters/cbc/adapter.py:63-65`

**问题**：`_cbc_config` 每次属性访问都 `load_config()` 读盘解析（`model_args` 每条消息触发）。

**修复**：缓存。

### 11. 异步循环内同步 `sleep` 阻塞事件循环

**位置**：`packages/core/adapters/cbc/adapter.py:337-380`

**问题**：`enrich_after_result` 内含 `time.sleep(0.2)`，在异步 `_read_stdout` 中同步调用阻塞事件循环 0.2s/次。

**修复**：改 `await asyncio.sleep` 或移出异步路径。

### 12. kimi wrapper 管道死锁隐患

**位置**：`packages/core/adapters/kimi/wrapper.py:106-131`

**问题**：先完全读完 stdout 才 `communicate()` 读 stderr；若 kimi 向 stderr 写超 64KB，进程阻塞、stdout 永不 EOF，`_forward_and_collect` 死等。`communicate()` 后 `proc.wait()` 冗余。

### 13. 每次检索全量加载 chunk

**位置**：`packages/core/memory/search.py:98`

**问题**：`get_chunks_for_search` 每次全量加载所有 chunk 并反序列化全部 embedding，O(N)/查询，大数据量不可扩展（端到端仍 JSON-bound，见 memory 审查 #21 遗留）。

### 14. QQ 同会话并发消息响应串线

**位置**：`packages/qq/plugin.py:320-345`

**问题**：`_pending[session_id]` 被后到消息覆盖，两任务设同一 event，响应串线。

### 15. QQ 插件命令路由失败后永不重试

**位置**：`packages/qq/plugin.py:48-67`（`_refresh_command_routes`）+ `:389-397`（`handle_message` 懒加载守卫）

**问题**：`_refresh_command_routes` 拉取失败时（`plugin.py:55`）仍置 `_command_routes_loaded=True`；而 `handle_message` 的懒加载守卫 `if not _command_routes_loaded`（`:396`）依赖该 flag。结果：Core 启动早期拉取失败一次后，后续消息不再重试，命令路由永久失效（静默回落到 LLM 路径）。`_startup` 里「will retry on first msg」的注释与实现矛盾。

**修复**：失败时保持 `_command_routes_loaded=False`（或改用「已尝试 + 指数退避」标记），使下次消息能重试。

### 16. manifest MCP command 未校验

**位置**：`packages/core/manifest_loader.py:188-205`

**问题**：`_parse_mcp_server` 对 `command/args/env/cwd` 不校验，manifest 可声明任意可执行文件（如 `cmd /c ...`），随后被 cbc 子进程执行（`memory_dir` 已有穿越防护，MCP 命令没有）。

**修复**：约束 command 可解析到插件目录内或白名单。

### 17. React 无 selector 订阅整个 store

**位置**：`packages/web/src/components/layout/Sidebar.tsx:39-40`、`SessionList.tsx:25`、`InputRow.tsx:186,193`、`SettingsPanel.tsx:28`

**问题**：`useXXXStore()` 无参解构订阅全部状态；流式期间 `addMessage` 高频触发导致整棵侧栏/输入区频繁 re-render。

**修复**：改用原子 selector。

### 18. editorStore setRoot 竞态

**位置**：`packages/web/src/stores/editorStore.ts:91-99`

**问题**：快速切换会话时旧 `fetchTree` 结果覆盖新树。

**修复**：加 sessionId 版本守卫。

### 19. `collapseAllGroups` 为 no-op

**位置**：`packages/web/src/stores/uiStore.ts:208-213`

**问题**：只复制当前集合、从未加入全部 key，「全部折叠」失效。

### 20. `_replaying` 无 try/finally

**位置**：`packages/web/server.py:1068-1077,1167-1176`

**问题**：中途异常会永久置 True，阻塞 stdout 追加。

### 21. `config.py` 浅拷贝污染默认值

**位置**：`packages/core/config.py:51-55`

**问题**：缺文件时 `dict(DEFAULT_CONFIG)` 浅拷贝，嵌套 dict（`remote` 等）与全局默认共享引用，调用方改动会污染默认值。

**修复**：`copy.deepcopy`。

## 建议优先级

1. **安全**：server.py 加 token 鉴权 + 默认限制 workdir 到 `WORKDIRS_DIR`；非回环 host 直接拒绝启动（#1 #2）
2. **正确性**：修 unbound `s`（#3）、kimi fork（#4）、草稿保存（#6）、`collapseAllGroups`（#19）
3. **并发/生命周期**：广播加锁（#8）、session 原子写（#9）、useWebSocket 清理（#5）、`_replaying` try/finally（#20）
4. **性能**：`load_config` 缓存（#10）、去同步 sleep（#11）、chunk 全量加载（#13）
5. **工程**：拆分 `server.py`（#22）与 `app.ts`（#30）；React 原子 selector（#17）；markdown chunk 代码分割
